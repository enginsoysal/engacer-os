# Engacer OS M14.3 / 0.14.3 - Windows files and persistent settings

Status: **development candidate; full native/public qualification remains open**. M14.2 remains the qualified public download. The records below are scoped development observations, not a final M14.3 publication receipt.

This stage implements checked Unicode paths and enumeration, kernel-owned generation-checked shared file grants, existing-file edits, synchronous byte-range locks, durable user registry values, copied process environments and temporary files. User file metadata is independent of app ownership. Application instructions execute through Engacer OS's own kernel and compatibility APIs; there is no embedded Windows guest.

Candidate build: `ee751b3d701e676254defe24d88acf67`, binding 642 compiled inputs.

- Candidate ISO SHA-256: `d87ef78cca0bf6fb5674273fb577b0aed1de4c23cf5c067e92a0a1b4e2adde2d`
- Candidate VMware ZIP SHA-256: `210a2498cd903d30337838fafe268f05813cda4ae52e683fd658bf919de78ec2`

The exact prepared ZIP passes owned headless VMware setup, restart with the ISO retained and two independent disk-only starts, with all shipped devices enabled and real guest input. Fresh compact 128-MiB, ordinary and actual 3840x2160 profiles also pass. Its disk is blank, growable 20-GiB SATA; the profile uses two CPUs and x64 UEFI with Secure Boot disabled. Installation erases the selected disposable disk. These named virtual tests do not establish universal hardware compatibility.

The original supported 7-Zip console/MSI installation, archive/extraction, removal and reinstallation pass, including all 106 original payload hashes. Original Notepad++ and SumatraPDF images remain inspection-only. Firefox remains a verified optional installer download; installation and execution are unavailable. Original Windows GUI and reusable MSI/EXE installer services follow in later M14 stages.

The selected file profile admits 128 shared objects and 32 grants per process, with lazy sparse dirty data capped globally at 8 MiB and logical file size capped at 64 MiB. Unicode simple-fold identity uses one 3,344-byte read-only kernel table. Search handles have sixteen generation-checked slots per process. The user registry bounds keys to 64, values to 128 and exact data to 2,048 bytes/value. Environment blocks grow lazily to 8,192 UTF-16 units with 64 variables. Unsupported device/network namespaces, full NTFS/reparse/ACL behavior, directory rename and asynchronous file I/O are not claimed.

The full lifetime, fault/cancellation and release gates remain open. Component resource limits and zero-retention development probes are not total OS RAM, original GUI performance or a faster-than-Windows benchmark. M14.15 remains the mandatory whole-system CPU/RAM/storage optimization gate.
