## What changes

The desktop uses one aligned grid with original 48-pixel icons, centered native
Inter labels, two-line ellipsis, full-name readback and distinct hover,
selection and focus. Previous/Next expose overflow; disabled page buttons have
no activation target. New objects are selected and revealed. Spatial keys skip
empty or hidden reference cells. A single click selects; double-click or Enter
opens. Tab activation uses the same validated route.

My files, Documents, Appearance and Recycle Bin are independent references.
Right-click one to **Hide desktop icon**; the background menu's **Restore
desktop icons** brings them back. Even a genuinely empty desktop with all four
hidden can reach Settings through Start and restore them after restart. These
display choices do not remove apps, required services or user files.

Real creation, rename, shortcuts, folder pins, recycle and original-location
Restore retain checked native storage operations. A document-and-arrow icon
identifies a reference without reading or executing its target during painting.
Deleting the shortcut preserves its target. Recycling a pinned folder removes
its pin; Restore restores the object and the user can pin it again.

Caption/grip capture suppresses hover on objects behind a moving window.
The test caught the earlier wrong hover/full-name state; the corrected build's
complete viewport matches full repaint at all twelve tested positions/scales.
This is rendering correctness, not an FPS or GPU-acceleration claim.

Fixed desktop BSS/data is **544,196 bytes**, **32 bytes** above M12.2. The hidden
reference preference occupies **16 bytes on disk**. Desktop tasks and reference
changes retain zero additional managed pages and no new allocation failures;
idle CPUs halt. There is no new icon cache, idle animation or per-window image.
[Measured resources](../../evidence/M12/3/resources.json) and
[how/why decisions](../architecture/desktop-m123.md) separate these quantities
from configured VM RAM and total kernel consumption.

## Install and try

[Follow the eight-step VMware guide](../handbook/install-m123.md), then
[use the desktop and shortcuts](../handbook/desktop-m123.md).
Use `EngacerOS-M12STAGE3-VMware.zip` or its matching
`EngacerOS-M12STAGE3.iso`. The ZIP contains a new blank growable 20-GiB SATA disk,
128 MiB configured RAM, two CPUs and UEFI with Secure Boot off. Every shipped
device stays enabled. The matching ISO may remain connected after installation.

Twenty release assets include media, native images/maps, both manifests,
notices, corresponding 7-Zip source and license material.

## Qualification and retained limits

The exact enabled-device VMware ZIP and separate QEMU SATA/UEFI and BIOS journeys
install, restart with their ISO retained and boot twice from disk. Native tasks
cover marquee/context/keyboard selection, rename, pins, references, recycle and
Restore, thirty-three GUI-created overflow folders, disabled paging and actual
150%/3840×2160 display. Independent stored directories, pin bytes, the new
16-byte preference and bundled guide are checked. A separate fresh empty-desktop
installation and disk-only restart verify recovery with every reference hidden.
Agent visual/task review is distinct from a human usability study.

Free icon placement, arbitrary Unicode filenames, universal hardware/Windows
compatibility, ARM and vendor GPU 3D are not qualified. Existing entry/name,
window and provider limits remain. Files, taskbar and later desktop refinements
continue in the approved M12 order; complete final regression remains M12.18.

**Retained open observation:** an earlier M12.2 candidate had a concurrent BIOS
AHCI installation timeout. Its repeat passed, but the trigger is not isolated;
stress reliability remains unqualified. M12.3's passing named journeys do not
resolve that observation. Final M12.18 qualification must revisit it.
