## New interoperability tasks

The unchanged original 7-Zip file manager copies a Unicode filename into the native Text Editor. Saved bytes reopen after closing the editor and match independent stopped-disk reads. Cursor, backspace and delete preserve complete UTF-8 scalars. Malformed documents leave the current document unchanged.

The original 7zG.exe helper visibly opens Add to Archive. Its real Browse action opens the owner-bound native Save dialog, Cancel returns without changing the result, and a Unicode selected path returns to the original control. Selecting Save alone creates no file. Native Cancel task ends the original process group and releases its resources. This does not qualify normal C++ cancellation or complete GUI archive operations; original combo/check controls remain visually incomplete.

Owned classic Open/Save tasks exercise Unicode reading/writing, cancellation, short buffers, supported structure versions, filter selection, replacement consent and exact persistent bytes. Separate real timer-driven tests destroy the owner, exit its thread and exit the process while a native dialog is actually displayed. The pending request is generation-bound, abandoned buffers remain unchanged, and waiting CPUs halt. These owned ABI/lifetime tasks support the original journeys without replacing them.

## Display and resource profile

Native text consumes UTF-8 scalars. Selected Latin-1, Turkish and euro glyphs use exact Inter masks in ordinary/secondary faces; unsupported scalars use one replacement glyph. This is not arbitrary script shaping, IME or a runtime font engine. The original 1045 glyph masks remain exact, with 618 additional masks. Logical monitor/work-area dimensions remain consistent with window and pointer coordinates at 4K/200 percent.

Fixed desktop session state is 557684 bytes, eight more than M14.5. Sparse window pointers add 768 kernel bytes separately; individual windows remain lazy. Font coverage data decrease from 251248 to 227452 bytes; added glyph descriptors use 9888 bytes. Classic-dialog inputs fit one lazy request page. Shared sections use actual common physical pages with independent handle/view lifetimes. These are component measurements, not total OS RAM or a Windows speed comparison. M14.15 whole-system CPU/RAM/storage optimization remains mandatory.
