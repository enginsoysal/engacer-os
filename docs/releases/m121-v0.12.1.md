## Changes

Desktop buttons and text fields share readable light/dark states, hover, press,
disabled presentation and visible keyboard focus. Activation remains on release
inside the target. The Files scrollbar uses actual row counts, thumb dragging,
track paging, Home/End and cancellation; its keyboard ownership cannot leak into
the USB view or address field. Start letters, selected text and desktop feedback
use the same accent contrast decision.

Inter body, secondary, section and heading masks use actual physical sizes at
100/150/200%. Shared masks reduce coverage by 19,662 bytes compared with M11.6.
There is no new continuous animation or per-window framebuffer. App icons and
unified USB navigation are later ordered stages, not features claimed here.

## Install and use

[Follow the eight-step VMware guide](../handbook/install-m121.md) and
[try the shared controls](../handbook/components-m121.md).
Use the complete matching `EngacerOS-M12STAGE1-VMware.zip`, or its matching
`EngacerOS-M12STAGE1.iso`. The starter contains a new blank growable 20-GiB SATA
disk, 128 MiB configured RAM, two CPUs and UEFI with Secure Boot off. Installation
is real; no installed user disk is included. The matching ISO may remain attached.

The release asset set includes the ISO, VMware ZIP, build/starter manifests,
native images/maps, third-party notices, corresponding 7-Zip source and license
materials. `M12STAGE1-SHA256SUMS.txt` covers the other 19 assets.

## Qualification boundaries

M12-STAGE1-VM-v1 is stage-specific: native QEMU SATA/UEFI and BIOS installation,
retained-ISO restart, two ordinary disk boots, the exact enabled-device VMware
starter, component/focus/scroll input, real 150% and 3840×2160 rendering, bounded
resources and cached/full movement comparison. The complete controller/device
and original-application regression remains M12.18. M11.6's broader matrix is
historical proof for its own immutable bytes, not inherited proof for M12.1.

Physical hardware, ARM, vendor GPU 3D, general DOS/Windows compatibility and a
human usability study are not qualified by this stage. Agent scenario and visual
review are explicitly separate. [Implementation decisions](../architecture/components-m121.md)
record fixes and limitations; [current status](../roadmap/status.md) tracks the
ordered remaining stages. GitHub assets and the native BrixCanvas homepage must
pass fresh readback independently of native runtime acceptance.
