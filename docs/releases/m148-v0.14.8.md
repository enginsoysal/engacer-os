# Engacer OS M14.8 - Original x64 EXE installer lifecycle

M14.8 native/source/media qualification passes: 105 native and 41 supporting host groups across 147 campaign tasks, including actual VMware installation and two independent starts. Original SumatraPDF 3.6.1 x64 EXE GUI installation, cold removal and cold reinstall pass. Both installation cycles verify four original payloads and two actual shortcuts. The PDF reader itself remains unqualified. Previous 7-Zip and Notepad++ MSI scopes are retained. Build fdb650a0e4cff632bd4945cc1b024567 binds compiled source bd12730bf19eee5a4ab496d798a7c0435728fed0 and 825 exact inputs. GitHub downloads and independent public content checks are being finalized. Native homepage Save is blocked by the reproduced BrixCanvas website-read error; article synchronization works. A stale homepage is not counted as successful publication.

## What changes

Windows Apps reviews MSI and EXE sources without running their custom actions.
The M14.8 EXE broker runs the pinned original SumatraPDF 3.6.1 x64 installer
and uninstaller through Engacer OS's own kernel and Windows compatibility APIs.
The application instructions execute natively; VMware is the external test
host, not an embedded Windows guest. The installer and vendor DLLs are unchanged.

The confirmed operation grants access to its own product folder, two approved
shortcuts, scoped per-user registrations and a private temporary namespace.
Product ownership is protected outside that folder. Completion requires real
child exit, independent payload and shortcut verification, and durable state.
The original uninstaller's self-copy helper and limited command batch perform
real cleanup. Unrelated documents and the source download are preserved. Changed
or extra product files refuse destructive removal before the original recursive
uninstaller can erase them.

The production-media chain verifies installation, a cold original removal and
a cold reinstall. Both installation cycles independently hash four original
payloads and parse both actual shortcuts through the Windows-native link reader.
The earlier original 7-Zip and Notepad++ MSI lifecycle scope is retained.

## Test scope and corrections

All 147 campaign tasks pass: 105 native groups, 41 supporting host
groups and the matching VMware starter. These include BIOS/UEFI ISO/USB
installation, independent disk starts, ordinary/compact/4K paths, repeated GUI
fault containment and actual enabled-device VMware installation and starts.
Final evidence records the completed result rather than inferring it from a
successful build or a selected application.

A real integrated snapshot/mapping handle collision was corrected with separate
handle domains and native coexistence tests. The rejected candidate is preserved.
Two owned historical paint/fault probes now compare selected-font API metrics
instead of assuming a fixed 16-pixel height; their 21 lifecycle/fault repetitions,
pixel checks and zero-retention requirements remain. Original vendor bodies and
historical accepted sources are not edited. A final generation guard also rejected 99 obsolete refusal keys; both the
exact generated table and diagnostic inventory were corrected before rebuilding
and rerunning the full campaign. One initial 4K control observation
refused; its unchanged repeat passed. No cause or OS fix is inferred from that
repeat.

## Resource measurements and limits

The measured final-media EXE install, removal and reinstall respectively peak at
7611, 3666 and 7611 native managed pages. Measured retained page deltas are 1, 5 and 1.
The session UI cache accounts for one retained page; four additional retained
allocator pages in the removal measurement are not attributed. These are bounded
task observations, not total OS RAM, a zero-retention claim or a Windows speed
comparison. Configured VM RAM, framebuffer, fixed load and caches are separate.
Whole-system CPU/RAM/storage optimization remains the M14.16 release gate.

The PDF reader itself, preview/filter operation, arbitrary EXE installers, general
MSI packages, Notepad++ editor use, Firefox execution and universal Windows x64
compatibility remain unqualified. Close the finished original installer using
its title-bar X; its Start SumatraPDF action is not a qualified reader launch.
Interrupted EXE records can be inspected; automatic EXE rollback is not offered.

Canonical fonts provide actual metrics and bounded drawing, but the original
decorative SumatraPDF logo is clipped with the fallback font. This is not
pixel-identical Windows rendering.

The approved future platform plan is M14.9-M14.16, not a fixture whitelist.
After M14.8, work stops before M14.9 as requested. BrixCanvas platform findings
remain in the combined report. The native homepage Save error is recorded
separately from the working GitHub-driven article publisher; a stale homepage
is not counted as successful publication.
