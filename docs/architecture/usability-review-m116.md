# M11.6 installation and desktop review

This is an agent's scenario and native-screen review, not a study with children,
older adults or other participants. Final acceptance requires the matching
regression reports; visual review alone cannot establish installation success.

The review asks, at every ordinary step: is the next action clear, convenient,
friendly, visually consistent and readable for someone with little IT experience?
It retains the M11.5 visual system rather than introducing a different interface
during final qualification.

| Step or task | Clarity and convenience review | Native verification |
|---|---|---|
| Welcome | One prominent Next action, eight visible steps, offline explanation and separate recovery route | Welcome capture; ordinary pointer and keyboard input |
| Keyboard / size | Named layouts, a real typing box, Clear and explicit size choices; unsuitable sizes keep the previous value with an explanation | Actual QWERTY/Dvorak typing, size refusal, ordinary/150%/4K buffers |
| Disk | Bordered list, whole-row click target, empty/filled radio selection, capacity, eligibility reason and disabled Next before selection | Unselected and selected captures; actual admission and foreign-disk preservation |
| Disk tools | Partition/free-space rows and target-specific operations lead to separate review and consent | Create/delete/format, cancelled/unchecked review, independent data hashes |
| Apps | Required services are explained; presets and individual choices retain state across pages | Minimal installed desktop and actual offline Calculator install/run/remove |
| Style | Local name, accent, light/dark and wallpaper choices remain visible in Review and affect the installed desktop | Saved records plus actual installed presentation and subsequent boots |
| Review | Disk, capacity, account, keyboard, app count and appearance appear together; install explains real writes | Back clears destructive consent; no writes before explicit final authorization |
| Install / Ready | Progress reflects copying and checking; failure cannot be presented as success; Ready's primary action restarts | Retained-ISO platform reset, installed-volume identity and two detached starts |
| First desktop | Optional welcome card can be dismissed without installing another app; dismissal persists | Minimal profile and independent boot readback |
| Files and shell | Single click selects; Enter/double-click opens; context menus show capabilities; destructive actions have review | Real stored files, conflicts, recycle/restore, protection, pins, search and removal |
| Windows | Caption commands, edges/corners, keyboard menu and switcher retain focus and saved normal geometry | Exact viewport comparisons, USB/PS2 routes and saved appearance |
| Errors / recovery | Explain the target and next useful action; quarantined storage stays blocked until restart and repair | Actual injected write failure, retry on the same disk/NVRAM and boot-slot repair |

Native frames use Inter coverage fonts, semantic sizes, measured text, consistent
spacing and bounded clipping. Setup checks that all interactive rectangles fit
inside its panel and meet the 36-pixel logical minimum used by this wizard.
Ordinary and HiDPI captures are decoded from real framebuffer bytes. No screenshot
resizing is used to claim 4K support.

Long labels can use bounded ellipsis. The secondary More apps caption is shortened
at the ordinary viewport; the visible More action and matching handbook explain
pagination. This is a small wording refinement for a later design pass, not a
claim that every caption is ideal. Disk identity, capacity, review targets,
primary navigation and error explanations must remain usable.

The final regression also records two harness corrections: M11 creation dialogs
must be checked through durable entries, and a USB folder row is selected by one
click and opened with Enter before exporting into it. Restoring pre-M11
single-click navigation merely to satisfy an old test would contradict the
owner's requested interaction model.

Resource observations distinguish fixed state, managed pages and shared buffers.
Unchanged idle paints and halted CPUs are measured. Host event-to-drain timings
include observation and emulation overhead; they are not refresh-rate or FPS
measurements and do not establish vendor GPU acceleration.
