# Find your way around the Engacer OS documentation

The [documentation portal](https://engaceros.brixcanvas.com/blog/documentation) starts with what you want to do. Its current installation instructions follow the qualified download and matching release guide. M13.0 remains the original design package; subsequent native stages have their own scoped media and tests.

1. **Start here:** understand current capabilities and read the desktop introduction.
2. **Install:** download the ISO or prepared VMware ZIP, follow installation, then check the matching tested scope.
3. **Use Engacer OS:** apps, windows, folders, file transfers, dialogs and USB removal.
4. **Customize:** supported Settings, keyboard/accessibility and distribution profiles.
5. **Project & development:** the current roadmap, Windows compatibility work, architecture and contributing. Historical M13 plans and original concepts remain in the archive.
6. **Downloads:** the qualified native release and checksums; older downloads remain separately archived.

The [history and full reference](https://engaceros.brixcanvas.com/blog/documentation-archive) retains previous milestones and earlier technical/user documents. An old installation article does not become current because its publication date changed. Existing article URLs remain available.

## Search and article navigation

Choose **Search documentation**, or press **Ctrl+K** (**Command+K** on supported host keyboards). The panel searches the current published guide index without leaving your page. Type ordinary task words, use Arrow keys and Enter to open a result, or Escape to close and return focus. Include archived documentation only when you need history. Clear starts over; Browse documentation and Full search remain fallbacks. Articles provide a task sidebar (Browse documentation disclosure on narrow screens), an On this page heading list where headings exist, and Previous/Next in the configured task order. These M13.1 production features are separate from the original M13.0 prototype.

The BrixCanvas 404 recovery renderer currently keeps a **Search** link to the separate search page rather than rendering this panel. Its Home, Install and Downloads links remain available. This is a platform limitation, not a second recommended search flow on ordinary pages.

Every native stage must publish its matching guide/downloads and verify the actual website before the next stage starts.
