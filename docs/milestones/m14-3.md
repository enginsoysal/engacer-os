# M14.3 - Files, paths and persistent settings

Status: **in progress**. M14.2 native and complete public delivery pass; its ISO, VMware package, tag and accepted evidence remain immutable. [M14.2 receipt](../../evidence/M14/2/publication-results.json). M14.3 has no qualified public media yet.

Native development tests now pass for checked Unicode paths/search, shared files and blocking byte locks, persistent user registry/restart, copied process environments, safe temporary files and file-owned metadata surviving application removal. Each has twenty-cycle resource checks where applicable, plus the original supported 7-Zip lifecycle. [Implemented contracts, bounds and exact evidence](../architecture/files-m143.md). Full M14.3 regression and native/public release gates remain open; these observations do not promote development media to a qualified download.

## Concrete gaps

The preceding Windows CreateFileW adapter ignores sharing/security/template arguments, uses reusable raw file-slot handles, and refuses opening an existing file for modification. Its registry adapter reads selected strings from the installed product's registry.txt; it cannot create or persist application preferences. Native persistent storage exists, but that alone does not supply Windows namespace, handle-sharing or registry semantics. Environment-variable APIs and inherited variable blocks also need real implementation.

## Ordered implementation

1. Add strict bounded Windows path conversion, case-aware existing-component resolution, correct root/relative/dot handling and explicit refusal of unsupported device/network namespaces. Preserve Unicode names and original stored spelling without broadening the protected native roots.
2. Add kernel-owned generation-checked file grants, atomic read/write/delete sharing, existing-file edits, flush/close semantics, selected delete/rename and byte-range locks. A second process must observe the same file object; a runtime-local table cannot enforce cross-process access.
3. Add actual user registry key/value creation, query, update, deletion and enumeration with rights and size/error behavior. Persist acknowledged updates through the existing native COW/CRC storage path. The existing installed machine-registration view remains separate from writable user preferences.
4. Add real process-local environment variables, Unicode/UTF-8 API views and a copied child environment. Updating a variable in one process must not mutate another process's block or its protected path grants.
5. Qualify original supported 7-Zip file tasks plus purpose-built Windows sharing/settings probes, independent reboot/readback, cancellation/fault cleanup and bounded resources. Finish matching English guides, GitHub media and the actual complete website before M14.4.

## Acceptance

Use only owned disposable images. Test case/Unicode/path boundaries, create dispositions, stale handles, conflicting access, rename/deletion and locks across private parent/child processes. Check exact native stored bytes, not only successful API return values. Save preferences and documents, stop the guest, start independently from disk and read them back through the Windows APIs. Missing and denied paths must return the selected correct errors without exposing another user's or system files.

Retain the original MSI install/run/archive/extract/remove/reinstall task and 106 payload hashes. Repeat exact-source thread/TLS/exception ownership checks where the new file/registry state affects lifetime. Measure fixed, peak and retained memory separately; twenty repeated closes must have zero unexplained retention. Blocked work must halt rather than introduce a new polling worker. Qualify compact/ordinary/actual 4K installation and independent starts, then the exact enabled-device VMware ZIP and all public delivery gates.

Full Windows GUI controls, general COM, arbitrary MSI/custom actions, NTFS/reparse/network filesystems and general Windows application compatibility are not inferred from this stage. Limits must be explicit; unsupported operations fail instead of silently succeeding.
