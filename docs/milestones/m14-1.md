# M14.1 - Win64 loader and DLL environment

Native qualification: **M14-STAGE1-VM-v1**, build `23b939c5a022246412fcac648f5f4453`. GitHub release and actual complete website delivery close separately; their publication receipt is required before M14.2.

## Delivered behavior

Original AMD64 PE files are streamed into checked demand-backed private mappings. The image/file limit is 32 MiB, with 32 module slots, a 128-MiB virtual budget and the existing 10,000-page physical ownership bound. Guard ranges, read-only and non-executable permissions remain enforced. DLL search stays application-local, with named/ordinal/forwarded exports, validated original delay thunks, dependency reachability and external-reference unload/reuse. ExitProcess ends the protected native task rather than supplying a success stub. Static TLS and broader process/thread/exception semantics remain M14.2.

Windows Apps has a shared **Check a Windows file** picker. It reports an original image's mapping/import layout without executing its code. The selected original Notepad++ and SumatraPDF images now map despite exceeding the old eight-MiB bound. Their interfaces and installers are not qualified by inspection.

Browser choices offers the original Firefox 160.0.1 x64 offline MSI directly from Mozilla. The real transfer supports cancellation and a subsequent complete download. Firefox installation and execution are unavailable. Chrome, Brave and Microsoft Edge remain candidates. Downloads stream to storage with a 128-MiB cap; the basic reader's separate 128-KiB page limit remains.

## How and why

See [loader architecture](../architecture/loader-m141.md). Fixed 16-MiB module slots could overlap the larger originals; bounded first-fit image reservations replace them. Non-present reserved pages avoid allocating all zero-filled image space in advance. Original headers/sections are copied directly, avoiding a redundant full-file heap copy. References and dependency reachability prevent both premature unload and permanently consumed module slots.

The new build identity also receives the existing complete semantic font set. A real 4K startup test exposed the missing work-directory admission before release. The build rule is corrected and a compile-time table-size assertion prevents recurrence. The frozen font header matches the existing raster lock exactly: 251,248 coverage bytes. [Development failures and corrections](../../evidence/M14/1/development-observations.json) remain recorded honestly.

## Exact-candidate checks

- Ordinary 1920×1080/512-MiB, compact 1280×800/128-MiB and physical 3840×2160/1024-MiB profiles install, restart with ISO retained and start twice independently without ISO. Completed Settings tasks retain zero managed pages; short quiescent observations show halted CPUs and no repaint changes.
- The exact prepared VMware package installs and starts with every shipped device enabled, obtains DHCP, exercises real desktop controls and starts twice without ISO. Existing user VM inventory is unchanged.
- The original 7-Zip MSI installs, runs, archives, extracts, removes and reinstalls. All 106 original payload hashes agree with pinned provenance.
- Original Notepad++ and SumatraPDF image bytes, relocations and import structure are checked in the actual protected worker, with independent mapped-byte fingerprints. Invalid input is refused and measured repeated tasks retain zero pages after the one-time four-page kernel transition stack.
- Twenty synthetic Windows PE executions touch a sparse 24-MiB image, bind named/ordinal forwarded imports, reuse a DLL slot through 48 load/reference/free cycles, and execute a genuine deferred import after its call marker. Attachment/detachment counts and original PE delay-directory presence are checked. Peak owned physical memory is 134 pages, with zero per-task retention. This is a loader fixture, not GUI app performance.
- Actual CPL3 attempts to execute non-executable data, write read-only data and access an unmapped guard are contained. Repeated attempts retain zero additional pages and the desktop can still launch another app.
- Native HTTPS cancellation publishes no partial Firefox MSI. A subsequent 95,924,224-byte download independently matches Mozilla SHA-256 `6dc28633cbd77cb1d044f339185cd467dda39397e4bcca942bfb0ddb2360c681` on the stopped owned disk.
- Production HTTP parsing passes fragmented/framing/limit cases and 5,000 mutations. Production storage streams a Firefox-sized fixture with 4-KiB body chunks, verifies CRC/hash, and refuses over-budget, cancelled and existing-target publication.

## Remaining limits

No general Windows GUI/MSI, Firefox runtime, static TLS, normal process-detach callback, x86, Win16/DOS, GPU gaming or universal hardware compatibility is claimed. The one-time transition stack is fixed infrastructure, not unexplained task retention. Short idle checks are not another long-duration stability soak. Observer wall times and scheduling quanta are not Windows CPU-time benchmarks. M14.15 remains the mandatory whole-system optimization and final release gate.
