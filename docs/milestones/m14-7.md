# M14.7 - Reusable MSI execution

In development after the accepted M14.6 native/public delivery. M14.6 remains the qualified download. No M14.7 native behavior or media is accepted yet.

## Ordered implementation

1. Inventory the unchanged selected MSI tables and actual cabinet/custom-action payloads. Retain original versions and hashes; do not execute an installer on the development host.
2. Implement bounded properties, formatted fields, conditions, directory/component/feature selection and sequence planning. Reject unsupported mandatory actions before changing the target.
3. Replace the one-digest adapter with data-driven standard actions, exact payload verification, durable product ownership and recoverable transactional writes. Preserve personal and modified files on removal.
4. Execute required original x64 custom-action code through the native PE/API environment, with real MSI session/property/record services and the required child cmd/xcopy behavior. Do not replace or skip the original WiX DLL to advertise success.
5. Qualify original 7-Zip and Notepad++ installation/removal/reinstallation, conditions, cancellation and fault recovery, plus retained native runtime/desktop regressions and matching VMware installation/independent startup.

## Resource and safety requirements

Allocate package/session state lazily, enforce explicit limits on properties, recursion, tables, paths, files, cabinet expansion and pending actions. Free transient state and verify zero retained owned resources. Never silently expand whole-system reservations or poll blocked tasks. Use disposable owned VM disks only. A missing mandatory action or required API blocks the affected original task rather than returning fake success.
