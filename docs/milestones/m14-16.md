# M14.16 - Whole-system optimization and independent-bundle release

Status: planned, not started. Revised by owner instruction on 23 November 2026.
This document schedules future implementation; the current task only edits plans.

Mandatory contract: [independent Windows app environments](../architecture/windows-app-environments.md).
No global application registry or shared app dependencies. Two apps needing the
same component receive independent copies.

## Goal and dependencies

Optimize and qualify the exact working M14 system after M14.15, preserving the
owner's no-cross-app-sharing rule. This is the final integrated optimization
gate, not permission to undo isolation for a smaller benchmark.

## Work to perform

1. Measure cold/warm launch-to-interactive time, real app computation, total
   CPU/idle work, private/peak/retained RAM, input latency and broker/kernel costs.
   Measure actual filesystem and block bytes/requests/flushes, drained writeback,
   duplicate installed footprint and update/rollback peak storage.
2. Preserve independent installed copies for identical dependencies. Audit
   filesystem backing, module caches and physical app-code mappings; reject
   cross-app hard links, reflinks, deduplicated runtime stores or page coalescing.
3. Optimize demand loading, app-local indexes/caches, bounded buffers, metadata
   lookup, verification scheduling, on-demand services and event-driven waits.
   Do not introduce a permanent dependency scanner or global runtime daemon
   that makes app removal unsafe.
4. Attribute kernel/platform shared infrastructure separately from private
   dependency costs. Include all compatibility/device work in whole-system
   measurements; do not compare configured guest RAM with process use.
5. Preserve seven cold/seven warm sample protocols and twenty repeated
   lifecycle/resource checks where applicable. Record raw samples, median/p95,
   cache limitations, workload/version identities and reproducible budgets.
6. Resolve unexplained retained allocations and regression thresholds before
   release. Investigate the M14.8 removal measurement's four unattributed pages;
   do not label them a known cache or assume their cause.
7. Freeze compiled inputs and artifacts; rerun the full native, original-app,
   A/B independence, all-three-routes, recovery, hardware and physical rendering
   corpus on matching release media. Update stage-number tooling for M14.16.
8. Publish matching ISO/USB/VMware media, source/licence provenance, scope,
   tutorials and private-dependency workflows. Independently download assets
   and verify actual website content, routes, source links and current homepage.

## How and why

Duplicate dependencies have a real storage and possible RAM cost. Measure it
honestly and optimize avoidable work inside each owner, not by secretly
reintroducing dependency coupling. Correct behavior, saved documents, ownership
and readable interfaces are release requirements, not benchmark tradeoffs.

## Deliverables

Raw functional/performance reports, budget/regression decisions, exact-source
media manifests, independent download/website evidence and documented remaining
compatibility work. No faster-than-Windows claim without comparable workloads.

## Acceptance and tests

- All three dependency entry routes and original lifecycle tasks pass on exact
  final media with no cross-app dependency fallback.
- Removing/updating A still leaves B fully functional after reboot, including
  identical runtime/DLL cases and concurrent service/device use.
- Private backing audits pass and duplicate storage is reported, not hidden.
- CPU/RAM/I/O/latency and retention meet the frozen budgets with all relevant
  OS/runtime/device work counted and no unsupported success placeholders.
- Public media, committed compiled inputs, English guides and actual website
  content agree. A blocked website Save is recorded, not falsely accepted.
- M15/x86 and M16/Win16-DOS remain separate execution expansions; neither is
  declared complete by a successful x64 package or app-environment design.

## Recorded input from M14.8

The [original EXE measurement](../../evidence/M14/8/original-exe-resource-measurements.json)
records retained managed-page deltas of 1, 5 and 1 for cold install, removal and
reinstall. One UI session-cache page is identified; four further removal pages
are not attributed. Attribute ownership and settled/repeated behavior before
final optimization claims. This is tracked future work, not a known root cause.

## Stage closure

Run meaningful contract, original-code, A/B ownership, persistence/failure and
resource tests for actual implemented behavior. Publish exact evidence, current
English manuals, GitHub source and actual website content before advancing.
Preserve historical media. No automatic approval to start this stage is given
by this planning revision.
