## Initial implementation

The development runtime adds bounded preemptive thread contexts, separate TEB/stack/FPU state, suspended creation/resume, timed sleep, expected-value park/wake and generation-bound thread handles. Dynamic TLS and last-error values move to per-thread state; a recursive blocking runtime lock protects the heap. A Windows-thread probe exercises four threads, joins, return codes, sleeping, recursive critical sections and independent TLS. The first exact-source development candidate (`4434b9f826769985c15080cc83c7e771`, 617 compiled inputs) passes the actual CPL3 probe: four threads, distinct IDs/TLS, suspended/resumed start, recursive contended locks, timed sleeps, wait-all and real return codes. Twenty repeated closes retain zero managed pages. [Native development proof](../../evidence/M14/2/development/threads-native.json). A 128-MiB compact installation, retained-ISO restart and two independent disk-only starts also pass. [Startup proof](../../evidence/M14/2/development/compact-startup.json). These are development checks, not full M14.2 qualification.

Normal process exit now dispatches DLL detach notifications in reverse order while retaining mappings. The production dispatcher passes eight host checks, including reentrant/idempotent cleanup and the non-null process-termination argument. [Host-only evidence](../../evidence/M14/2/development/lifetime-host.json). These callbacks still require exact-candidate native qualification.
