## Initial implementation

The development runtime adds bounded preemptive thread contexts, separate TEB/stack/FPU state, suspended creation/resume, timed sleep, expected-value park/wake and generation-bound thread handles. Dynamic TLS and last-error values move to per-thread state; a recursive blocking runtime lock protects the heap. A Windows-thread probe exercises four threads, joins, return codes, sleeping, recursive critical sections and independent TLS. The first exact-source development candidate (`4434b9f826769985c15080cc83c7e771`, 617 compiled inputs) passes the actual CPL3 probe: four threads, distinct IDs/TLS, suspended/resumed start, recursive contended locks, timed sleeps, wait-all and real return codes. Twenty repeated closes retain zero managed pages. [Native development proof](../../evidence/M14/2/development/threads-native.json). A 128-MiB compact installation, retained-ISO restart and two independent disk-only starts also pass. [Startup proof](../../evidence/M14/2/development/compact-startup.json). These are development checks, not full M14.2 qualification.

Normal process exit now dispatches DLL detach notifications in reverse order while retaining mappings. The production dispatcher passes eight host checks, including reentrant/idempotent cleanup and the non-null process-termination argument. [Host-only evidence](../../evidence/M14/2/development/lifetime-host.json). A subsequent development candidate also passes the actual DLL attach/detach sequence (50 matching notifications, including two remaining DLLs at process exit), twenty load/run/unload cycles and contained NX/read-only/guard faults. [Native development evidence](../../evidence/M14/2/development/dll-and-faults-native-v2.json). This is not the full M14.2 exception/unwind gate.

## Development observations and documentation upkeep

The first thread fixture lacked relocations and was correctly refused. Its fixture was fixed rather than weakening the loader. A later optimization exposed a real deadline defect: when all Windows threads slept, the desktop halted but no short timer deadline was armed, so the RTC woke it too late and a join timed out. The failed [test](../../evidence/M14/2/development/wait-deadline-diagnosis.json) remains preserved. The new candidate shares the existing PIT ownership between network and Windows deadlines, releasing it when no finite Windows wait needs it; The corrected development candidate `4fb82f97a6828ef4bdf86942cb8c1b83` passes the [expanded native thread/synchronization probe](../../evidence/M14/2/development/threads-native-v3.json): twenty repeated closes, 24 thread-close/reuse cycles per execution, named/auto/manual-reset events, wait-all non-consumption, semaphores, one-shot/periodic timer cancellation and observed CPU halt while blocked. A separate [native cancellation probe](../../evidence/M14/2/development/cancel-native-v3.json) cancels an all-sleeping process with three secondary threads 21 times; the one-time transition stack is four pages and subsequent measured retention is zero. This qualifies these development tasks, not all of M14.2.
