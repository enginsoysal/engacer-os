# M13.1 — One native visual and interaction foundation

Status: native implementation and M13-STAGE1-VM-v1 qualification pass. The exact M13.1 ISO and VMware package are published and independently downloaded/verified. Final matching-release website closure remains in progress; M13.1 is not yet closed.

## Changes and decisions

The new native candidate retains the existing smooth Inter masks, semantic font sizes and integer drawing paths. Shared M13 light/dark/high-contrast palettes refine the established component implementation; selected secondary controls use a softer selection surface, while primary actions retain a solid accent. The same production arithmetic is exercised over all 16,777,216 background colors, 1,572,864 state cases and 4,096 scroll geometry cases. Native appearance/input remain separate checks.

Settings → System → Interface preview exercises real buttons, selection and a bounded 48-character input without file or preference writes. It reuses the existing Settings application storage rather than allocating another per-window text buffer or adding an optional-app dependency. Keyboard focus and disabled controls follow the common native control registry. A prepublication review exposed rejected Shift input. The retained candidate-r3 failure reproduces it; the corrected field accepts Shift while refusing Ctrl/Alt/Meta text insertion. Every final native profile independently reads back capitals, punctuation and Backspace results.

M13 builds have a separate compiler flag, distribution profile, artifact prefix and external scratch directory. Historical M12 output is never rebuilt. Generated source/debug mappings redact external scratch paths. The existing 8-MiB live-kernel placement check remains enforced; no firmware memory is reclaimed to fit graphics changes.

Configured guest RAM is not OS consumption. The baseline reports separately record allocator counters and framebuffer bytes (8,294,400 and 33,177,600). These results do not qualify the new M13 candidate or a physical GPU.

An initial test failed because its pointer coordinate cache survived a guest restart. The failed report is retained in diagnostics; the harness now creates a new pointer after restart. No OS fix or pass was inferred from that test failure.
