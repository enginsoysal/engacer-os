# M14.9 - Environment contracts and compatibility reference laboratory

Status: in progress, started 26 November 2026. The [v1 environment contract](../architecture/windows-app-contract-v1.md) and [reference matrix](../../evidence/M14/9/README.md) record the first deliverables. The version matrix and milestone acceptance are open.

Mandatory contract: [independent Windows app environments](../architecture/windows-app-environments.md).
No global application registry or shared app dependencies. Two apps needing the
same component receive independent copies.

## Goal and entry condition

Freeze the independent app-environment contract before changing loaders,
registry storage or installers. M14.8 remains the qualified native release;
its evidence is not retroactively relabelled as environment isolation.

## Work to perform

1. Specify stable AppId, user, architecture, environment generation and owner
   identities; define which process/broker may create or change each identity.
2. Freeze a versioned bundle layout and manifest/transaction/dependency-record
   schema, including original source, component versions, graph edges, failures,
   permissions, private registry views, service instances and restart state.
3. Draw the boundary between private app components and native OS/kernel/device
   facilities. Ban cross-app DLL/runtime stores, link/dedup shortcuts and module
   cache reuse. Define minimal rebuildable shell/index records outside bundles.
4. Specify logical Windows paths and HKLM/HKCU/HKCR views, including x64/x86
   redirection and architecture-correct component lookup. Include Win16/DOS
   requirements in the format without claiming their execution is implemented.
5. Define owner-bound context tickets and failure-event records for all three
   dependency entry routes. Ordinary installation remains primary; dependency
   targeting in a separately opened installer is under Advanced.
6. Build the versioned Windows 7/8/8.1/10/11 reference matrix and a traceable
   missing-contract register covering APIs, runtimes, components and drivers.
   Compare actual results, errors, ordering and side effects using owned probes.
7. Inventory legacy M14.8 state and design conservative migration/reinstallation
   rules. Ambiguous legacy ownership cannot be guessed or silently shared.

## How and why

Use explicit contracts, not application-name special cases. Environment
identity becomes the common input to loader, registry, process and package
operations; later stages cannot each invent a different notion of ownership.
Reference traces distinguish an optional probe from a necessary missing runtime.
Record unresolved contract questions and their responsible later milestone.

## Deliverables

- Reviewed schemas/state diagrams, path/registry/object ownership matrix,
  threat and escape cases, migration decision and per-stage dependency graph.
- Reproducible reference-probe sources and version/source provenance.
- A test specification for two independent apps needing the same dependency.
- UI flow specification for automatic assistance, context-menu addition and
  ordinary installer Advanced targeting; no dependency-first default.

## Acceptance and tests

- Every resource class has an owner, storage location, access rule, lifecycle
  and implementation milestone. No global app registry/dependency pool remains
  an undocumented assumption.
- Walk through normal install, nested setup, a late .NET request, separately
  downloaded installer, incompatible versions, cancellation and removed targets.
- Specify negative cases for cross-app reads/writes, forged tickets, links,
  global service names, stale handles and ambiguous legacy records.
- Distinguish x64, required x86 helpers, standalone x86, Win16 and DOS execution
  requirements while retaining one management model.
- Architecture approval does not count as native runtime acceptance.

## Resource and handoff gate

Specify bounded metadata/events/graph depth and the CPU/RAM/storage protocol.
Freeze measurable baselines and attribution categories; do not invent zero
costs. M14.10 consumes the schemas, reference cases and ownership matrix.

## Recorded validation

The v1 schemas and reference comparison tool have executable checks. The
[lab result](../../evidence/M14/9/lab-check.json) captures accepted and rejected
record shapes and verifies missing and differing observations are reported.
The live host probe covers loader refusal and file lookup. The remaining
pinned Windows references in the matrix are required before full lab closure.

## Stage closure

Run meaningful contract, original-code, A/B ownership, persistence/failure and
resource tests for actual implemented behavior. Publish exact evidence, current
English manuals, GitHub source and actual website content before advancing.
Preserve historical media. No automatic approval to start this stage is given
by this planning revision.
