## Actual investigation

Read-only inspection records six original containers and 23 PE payload/embedded binaries, exact versions, SHA-256, file/image sizes, AMD64/x86 identity, static/delayed imports, TLS/exception/CLR directory presence and the current API registration names. The two original MSI databases are opened in read-only mode; table rows, package templates, action sequences and Binary stream bytes are independently read. No downloaded installer, custom action or app is executed on the development host. Host 7-Zip only extracts data; Microsoft Windows Installer only supplies read-only database reference observations.

## Concrete findings and decisions

- Notepad++ 8.9.9.1 x64 EXE setup is PE32/x86. Defer that installer route to M15. Its original x64 MSI, portable x64 app and embedded x64 WiX DLL provide an M14 target, subject to implementing its mandatory cmd/xcopy custom actions.
- Notepad++ SizeOfImage is 8,613,888 bytes; SumatraPDF 3.6.1 is 20,840,448 bytes. Both exceed the current eight-MiB loaded-image bound. M14.1 must provide checked, quota-bound larger mappings, not simply claim loader compatibility.
- The 7-Zip 26.06 payload includes original x64 GUI code and optional x86 shell-extension/SFX artifacts. Installed bytes are not proof those integrations execute. Preserve scope and ownership explicitly.
- Static import/name inventory identifies work but does not prove dynamic closure, correct APIs, original app execution, installer success or performance. All GUI targets remain investigated, not qualified.
