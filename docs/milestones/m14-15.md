# M14.15 - Independent app composition, broad compatibility and stability

Status: planned, not started. Revised by owner instruction on 23 November 2026.
This document schedules future implementation; the current task only edits plans.

Mandatory contract: [independent Windows app environments](../architecture/windows-app-environments.md).
No global application registry or shared app dependencies. Two apps needing the
same component receive independent copies.

## Goal and dependencies

Validate the complete private-environment system rather than a few installers
or isolated API probes. Retain the full Windows x64 product scope, including
required mixed-architecture helpers; missing required behavior feeds back to
its owning subsystem.

## Work to perform

1. Build a contract-driven original-software corpus spanning installer families,
   runtimes, services, helper chains, COM, device requirements and relevant
   Windows 7/8/8.1/10/11 behavior. Named apps remain fixtures, not a whitelist.
2. Run the mandatory A/B independence matrix with identical dependency names,
   hashes and versions, and with deliberately conflicting versions. Inspect
   physical ownership and actual execution, not just separate displayed folders.
3. Exercise install/start/use/close/update/repair/remove, cold restarts,
   concurrent execution, authorized background services and long-duration use.
   After every destructive A operation verify B's bytes/state and actual work.
4. Test late runtime requests, separately opened installers, Advanced targeting,
   context-menu addition, nested setup, resumed downloads and stale owner tickets.
5. Inject storage exhaustion, power loss, bad source/version/architecture,
   dependency cycles, failed activation, process/service crashes and device
   resets. Verify recoverable transitions and preserved personal documents.
6. Test cross-app escape attempts through paths/links, hives, module/assembly
   caches, named objects, brokers, service names and shared repair stores.
   Include multiuser identities, bundle relocation and duplicate imports.
7. Cover required external services, licences, trust/attestation, Windows
   version quirks and vendor integration. Private packaging does not implement
   these contracts or justify dropping necessary applications from scope.
8. Produce per-task compatibility evidence, unresolved-contract register,
   root-cause fixes and migration/reinstallation results for legacy M14.8 state.

## How and why

Isolation reduces cross-app interference but adds namespace/lifecycle contracts
that can themselves break software. Differential contract tests identify causes;
original workloads verify composition. Do not infer dependency completeness
from one launch, or full functionality from successful installation.

## Deliverables

Exact-source original workload matrix, reference/native comparisons, A/B
independence and recovery reports, stability observations and regression fixes.
M15 and M16 inherit the same matrix for their additional execution families.

## Acceptance and tests

- No A install, repair, update or removal mutates or invalidates B's private
  components. B still performs the registered workload after a cold start.
- Every registered workload has actual effects, source/environment identities,
  expected errors, persistence, resource observations and reproducible results.
- Broken optional probes do not create false dependency prompts; genuine late
  requests preserve target identity through manual and automatic repair flows.
- No application dependency resolves through cross-AppId storage or code pages.
- Preserve and investigate natural/forced failures; do not blame host hardware
  or declare unlimited stability without evidence.
- A finite corpus remains scoped evidence. Required unresolved functionality
  stays open rather than being converted into a universal compatibility claim.

## Resources and handoff

Measure representative concurrent and repeated private-runtime workloads,
retention and total system costs. Separate test-observer overhead, actual leaks
and bounded app-local caches. Freeze functional baselines and unresolved work
before M14.16 integrated optimization.

## Stage closure

Run meaningful contract, original-code, A/B ownership, persistence/failure and
resource tests for actual implemented behavior. Publish exact evidence, current
English manuals, GitHub source and actual website content before advancing.
Preserve historical media. No automatic approval to start this stage is given
by this planning revision.
