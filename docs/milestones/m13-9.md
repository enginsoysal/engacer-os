# M13.9 - Responsive motion and long-session stability

Status: investigation and implementation in progress. M13.8 remains the current scoped download. No M13.9 media or stability fix is qualified yet.

## Reproduced baseline and diagnosis plan

The owner identified M13.7. An exact enabled-device VMware starter ran without guest input for 3,600 real seconds. Its serial log accepted a subsequent Calculator launch, but 44 consecutive image samples remained identical from about 970 seconds and the final image still showed Files. The clock also stopped visibly. The test's original serial-only assertion passes input liveness; it does not pass visible responsiveness. Preserve [the failed visual interpretation, complete frame hashes and native log](../../evidence/M13/8/diagnostics/m137-one-hour-idle/review.json). A SVGA timeout is present; causation still needs isolation.

Inspect presentation ownership and timeout recovery, interrupt/time progress, input queues and bounded resource growth. Existing code stops issuing SVGA FIFO commands after quarantine while keeping the device configured for explicit updates. Test whether returning the device to an actual framebuffer-observation mode restores visible updates. Retaining a live input loop alone is not recovery. No screensaver workaround, accepted-media replacement, host desktop control or global VMware reconfiguration is permitted.

## Implementation and budget decisions

Preserve existing shared geometry, input ownership, clipping, partial invalidation, drag cancellation and reduced-motion semantics. Correct presentation recovery before adding effects. Prefer bounded counters and reuse existing framebuffer/shadow storage; do not allocate another full-screen surface or introduce idle polling. Record fixed state against M13.8 and M12.18, configured guest RAM, framebuffer/shadow bytes, managed peak and completed-task retention separately. New native media use M13STAGE9 only after source and complete assets are frozen; failed candidates remain diagnostics.

## Required qualification

- Real native input-to-visible feedback, drag/resize/scroll/menu transitions and independent pixels at 1920x1080, two vCPUs/512 MiB, and physical 3840x2160 at supported scale, two vCPUs/1 GiB. Publish method, median/p95 response, frame intervals and drops. Existing targets remain p95 ordinary feedback <=100 ms, drag interval <=33.3 ms at 1080p and <=50 ms at 4K. Host observation overhead is not guest-native FPS.
- Explicit presentation-failure recovery and actual visible ordinary input; preserve window/document contents and saved bytes. Test both the normal backend and its fallback. A serial event alone cannot pass.
- Real-duration corrected idle and active/idle cycles, with independently changed visible frames, clock/input/presentation progress and saved-data verification. An accelerated boundary probe is separate from elapsed time. Final M13.12 repeats this on exact final media.
- Compact/128-MiB capability checks stay separate from reference performance, with readable reduced-motion behavior, zero unexplained task retention and idle CPU halt.
- Exact enabled-device VMware ZIP installation, retained-ISO restart and two independent disk starts; matching English docs, immutable GitHub assets, native homepage/recovery Save and complete fresh desktop/mobile/source/link verification before M13.10.
